# 実験記録ガイド

更新日: 2026-09-06。実在する実験・データ・図の一覧は [結果・データ対応台帳](RESULTS_INDEX.md)。本書は今後の記録手順の正本とする。

## 目的

成功・失敗・未実行を同じ形式で残し、「どの仮説を、どのデータで、何と比較し、何を根拠に判断したか」を追跡できるようにする。実験の追加・再実行・結果修正と同時にレポートと台帳を更新する。

## 現行レイアウト（2026-09-05以降）

```text
experiments/
├─ README.md                  # 現在地・段階の計画
├─ RESULTS_INDEX.md           # 実行とデータ・結果の対応台帳
├─ RECORDING_GUIDE.md         # 記録手順
├─ E0/、E1/ …                # 着手した段階だけ作成
│  ├─ README.md              # 段階のレポート
│  ├─ config*.json           # 次回実行の設定
│  ├─ run_*.py               # 実験固有の実行入口
│  ├─ validate_results.py    # 保存結果の照合
│  └─ artifacts/<実行名>/    # 凍結した設定・データ・数値・図・由来
├─ src/                      # 共通実装
├─ tests/                    # 実装の検証
├─ templates/                # 記録テンプレート
└─ runs/                     # 旧系列の履歴
```

人間向けの正本は段階READMEまたは既存の実験別レポート（例: [TM_DYNAMICS.md](E1/TM_DYNAMICS.md)）。機械可読な正本は**各成果物フォルダ内**の設定・指標・summaryとする。段階直下の設定が後から変わっても実行時設定は保持する。台帳には正本への参照を置き、数値を複数の独立台帳へ重複保存しない。

旧 `runs/YYYYMMDD_STAGE_slug` は履歴として保持する。教材・クラウド添付内のコードやregistryを現行成果物と混ぜない。空の未着手段階や並行する共通ライブラリを作らない。

## 新規実験・追試の作成

1. [台帳](RESULTS_INDEX.md) で親実行・比較対象・未実行段階を確認する。
2. 対応段階の既存レポートへ [共通テンプレート](templates/experiment_record.md) の必要項目を記入する。異なる研究質問を独立して説明する必要がある場合だけ実験別レポートを追加する。
3. 仮説・反証条件・split・指標・事前ゲート・設定を固定し、目的が分かる未使用の出力名を決め、台帳へplannedとして追加する。
4. 実行後は台帳の同じ行を更新し、実際の出力・結果・検証・不足をリンクする。

現行runnerの再実験例（作業ディレクトリはプロジェクト直下）:

```powershell
python experiments/E1/run_e1.py --config experiments/E1/artifacts/fixed_readout/config.json --output experiments/E1/artifacts/fixed_readout_replication
```

実行前にrunnerの引数と実行時ソースを確認する。既存結果の厳密な再現には保存された設定・ソース・環境を使い、出力は別名にする。`new_experiment.py` は旧 `runs/` 形式専用であり、現行段階の生成コマンドとして使用しない。

このガイドは今後の記録運用であり、runnerによるMarkdown台帳の自動更新は未実装である。

## 実験ライフサイクルと判定

1. `planned`: 仮説、主指標、比較対象、成功条件、反証条件を先に書く。
2. `running`: 実行コマンド、環境、実データ識別子を記録する。
3. `completed` または `failed`: 図表と指標だけでなく解釈と失敗理由を書く。実行失敗と、完走した実験の仮説不支持を区別する。
4. `superseded`: 後継実行と置き換えた理由を書く。元の証拠は保持する。

実行状態とは別に、整合性検証を `passed / failed / not_checked`、科学的判断を `supported / rejected / inconclusive / not_evaluated` と記す。合否未達でも記録完了にはなり得るが、後段への移行許可とは別に判定する。既存JSONのスキーマを揃えるためだけに改変せず、レポートで対応づける。

## 必須のデータ対応記録

| 項目 | 残す内容 |
| --- | --- |
| 実行識別 | 系列、実験ID、成果物相対パス、実行日時とタイムゾーン、親実行、親から変えた要因 |
| 入力 | データパス、生成元/取得元、seedとRNG、初期値、形状・dtype・単位、burn-in・観測長。未保存なら再生成に必要なコード・版・条件と限界 |
| 行・配列の対応 | CSVの主キーと粒度、NPZの配列名・軸順、両者の結合キー。同じ軌道の窓・精度違い・交換対を独立標本として数えない |
| 前処理・split | 前処理統計の保存先、fit対象、train/validation/testの識別子・分割単位。データを共有した親実行と共有範囲 |
| モデル・選択 | 特徴配列、次元、候補選択記録、凍結した係数/モデル、test前に確定した設定 |
| 結果 | 個別予測、条件別・seed別指標、集約方法、区間の差の向き・再標本化単位、失敗条件も含むsummary |
| 図表 | 図のパス → 元CSV/NPZ → 列・配列・抽出条件 → 生成スクリプト/関数。理論曲線は式と設定への参照 |
| 由来・検証 | 実行時ソースZIPまたはcommit＋未コミット差分、環境・依存版・thread、実行/再利用/検証コマンド、SHA-256と対象範囲、検証結果 |
| 保管 | Git追跡済み/外部保管/ローカルのみの別。外部なら取得先とハッシュ、未保存ならその理由。ローカル存在をバックアップ済みと呼ばない |

合成データでも「synthetic」とseed一つだけでは不十分。パラメータ・初期値生成・RNG・コード版・配列順まで追跡する。該当しない欄は空白のままにせず理由付きで該当なしとする。

レポートは `Hypothesis / Change / Metric / Result / Interpretation / Next Action` が追える形を維持する。比較表に異なる実行の数値を載せる場合、各数値へ出典実行と条件差を付記する。

## 実行前チェック

- 一度に変更する主要因は一つか。複数変更なら、その理由と比較の限界が明示されているか。
- train/validation/testを軌道またはseed単位で分け、前処理・基底尺度・ハイパーパラメータをtestに適合していないか。
- ベースライン・反証条件・科学的ゲートが事前に書かれているか。
- Cauchyのような重い裾に対して、存在しない母平均・母分散を前提にしていないか。
- 学習する結合と固定する結合、状態時間 `t` と学習ステップ `n` の更新順を記録したか。
- エントロピーだけでなく復号・同期・結合正則化を別に評価するか。

## 実行後・記録完了チェック

- 成果物内の設定、実行時ソース・環境、入力または再生成条件を凍結したか。
- summary（旧形式ではmetricsも参照）から条件別・seed別結果へたどれるか。
- 図の元データ、生成処理、抽出条件、モデルのtest前凍結を記録したか。
- レポートの結果・解釈・判断・次の一手を更新し、不支持結果を削除していないか。
- [台帳](RESULTS_INDEX.md) に実行状態・データ・結果・不足を追記したか。
- 図や論文・スライドから元の実行と数値表へたどれるか。
- リンクが実在し、文書の行数・配列形状・判定が保存結果と一致するか。
- Gitのignore対象を含め、共有に必要な証拠の追跡状況または外部保管先を確認したか。

整合性の確認で科学的仮説を再判定しない。ドキュメント整理だけならリンク・スキーマ・保存ハッシュを読み取り確認し、重い実験や書き込みを伴うvalidatorを無条件に再実行しない。文書とデータの対応が未記録なら、計算が終了していても記録完了としない。

## IDと上書き方針

- 現行は「系列＋実験ID＋ `E<段階>/artifacts/<実行名>`」で一実行を識別する。旧形式のIDは `YYYYMMDD_STAGE_slug` のまま保持する。
- 同条件の再実行でも新しい成果物名を指定し、親実行を記す。E0の既存pilotと本実行のような同一IDを一件にまとめない。
- 既存成果物は整理目的で上書き・改名・移動しない。修正実験から元の実行へ参照を張る。
- 一時ファイルと保存する証拠を分ける。新しいフォルダは既存配置で表現できない場合だけ作る。
- 修正前の値と理由を残し、失敗結果や反証を消さない。ハッシュ台帳は自己参照を避け、対象外ファイルを明記する。旧実行の現在のハッシュを実行当時の証明として後付けしない。
