# 実験成果物の記録ルール

このプロジェクトでは、実験の追加・再実行・結果修正と同時に、対応するドキュメントを更新する。

1. 開始時に `docs/PROJECT_CONTEXT.md`、`docs/MIGRATION_MANIFEST.md`、`experiments/RESULTS_INDEX.md`、`experiments/RECORDING_GUIDE.md` を読む。
2. 現行実験は `experiments/E<段階>/`、共通処理は `experiments/src/` を再利用する。旧 `experiments/runs/` と教材・クラウド添付は履歴・参照資料として区別する。
3. 実行前に、系列・実験ID・成果物の相対パス・親実行・仮説・設定・seed・split・判定基準を記録する。同じ実験IDでも成果物パスが違えば別実行として扱う。
4. 実行後は段階のREADMEまたは既存の実験別レポートと `experiments/RESULTS_INDEX.md` を更新する。入力 → 前処理/特徴 → モデル/予測 → 条件別指標 → 図表 → 結論を、実在パス・配列名・行キーでたどれるようにする。
5. 実行時設定・ソース・環境・データの由来/ハッシュ・検証結果を残す。保存しないデータは再生成方法と不足を明記する。詳細項目は記録ガイドと既存テンプレートを使う。
6. 実行状態、数値整合性の検証、科学的仮説の支持を別々に記す。未実行、pilot、不合格、旧系列を成功した本実験に混ぜない。
7. 既存の数値・NPZ・図・ソースZIP・ハッシュ台帳を整理のために上書き、改名、移動しない。修正・追試は新しい成果物名と親実行への参照を持つ。未着手段階の空フォルダを作らない。
8. 完了時に文書リンク、実在データとの対応、Git管理/外部保存の範囲を確認する。データ対応表と考察が未記録なら、計算が終了していても記録完了とはしない。

このルールは今後の作業時に適用する記録手順であり、現在のrunnerが文書を自動更新することを意味しない。
